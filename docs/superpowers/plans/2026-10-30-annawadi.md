# Annawadi Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a browser-based 3D KSRTC-style bus game (landing page, local driver login, playable multi-stop route with many passengers).

**Architecture:** Pure TypeScript logic modules (route, fares, boarding, rating, vehicle, clock, profile) are unit-tested and know nothing about React or three.js. A Zustand store wires them into a day loop. React Three Fiber components render the scene and push bus state into the store; an HTML HUD reads from the store.

**Tech Stack:** Next.js (App Router), TypeScript, Tailwind CSS, three.js via `@react-three/fiber` + `@react-three/drei`, Zustand, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-30-annawadi-design.md`

## Global Constraints

- Working directory `C:\Dev\asd` is empty and not a git repo: Task 1 runs `git init` and creates the project at the repo root.
- No backend, no external 3D model files; all geometry is procedural.
- Desktop keyboard play only; `/play` shows a "best on desktop" notice on touch/narrow screens.
- No official KSRTC logo; livery is red and cream with an original "Annawadi" badge.
- All tunable numbers live in `src/game/constants.ts`: `APP_NAME` (the spec spells it "Annawadi" in the title and "Anawandi" in section 1; use one constant so it is a one-line change, default `"Annawadi"`), `CAPACITY = 40`, `RENT = 250`, `GOAL = 800`, `DAY_START_HOUR = 6`, `DAY_END_HOUR = 20`, `DAY_REAL_SECONDS = 480`, `BOARD_INTERVAL_S = 0.6`, `STOP_SPEED_MAX = 1` (m/s, "nearly stationary").
- Currency prefix `Rs.`; v1 route has 7 stops (2 termini + 5 intermediate).
- Controls: W/S, A/D, Space, H, E, C, R, P/Esc, M.
- `localStorage` access always wrapped in try/catch; profile key is versioned.

## Review Focus

- Corrupt/absent `localStorage` JSON on `/login` and `/play` → app still loads with an in-memory profile (Task 5).
- Bus full (40) with passengers waiting → they are skipped, not lost, and stay waiting (Task 3).
- Passenger whose destination is behind the current direction never boards a bus heading the other way (Task 3).
- Reaching a terminus with passengers on board → all alight, direction flips, no negative stop index (Task 2, 3).
- Door opened while moving faster than `STOP_SPEED_MAX` or outside a stop zone → nothing transfers (Task 6).
- Empty or whitespace-only driver name on login → rejected with a message (Task 10).

### Task 3: Fares and boarding logic

**Files:**
- Create: `src/game/logic/fares.ts`, `src/game/logic/boarding.ts`
- Test: `src/game/logic/fares.test.ts`, `src/game/logic/boarding.test.ts`

**Interfaces:**
- Consumes: `Direction`, `stopsAhead`, `stopsBetween` (Task 2); `CAPACITY`.
- Produces: `type Passenger = { id: string; origin: number; destination: number; fare: number; patience: number }`.
- `fareFor(stopsTravelled: number): number` — `10 + 5 * (stopsTravelled - 1)` (Rs.), minimum 10.
- `makePassenger(id: string, origin: number, destination: number, patience: number): Passenger` (fare via `fareFor`).
- `planTransfer(args: { stopIndex: number; dir: Direction; onboard: Passenger[]; waiting: Passenger[]; capacity: number; isTerminus: boolean }): { alight: Passenger[]; board: Passenger[] }` — pure; alighting = destination equals `stopIndex` (all onboard if `isTerminus`); boarding = waiting passengers whose destination is ahead in `dir`, in queue order, limited by free seats after alighting.

- [ ] **Step 1: Write failing tests:** `fareFor(1)` = 10, `fareFor(3)` = 20; alights those with matching destination; boards only forward-bound passengers when `dir` is `"forward"`; with 40 onboard and 3 waiting, `board` is `[]` and nothing is dropped from the waiting input; with 39 onboard, 1 alighting and 5 waiting (all forward-bound), exactly 2 board (38 remain after alighting, so 2 seats are free); at terminus all onboard alight and nobody boards in the old direction.
- [ ] **Step 2:** Run both test files → FAIL.
- [ ] **Step 3:** Implement `fares.ts` and `boarding.ts` (no mutation of inputs).

**Interfaces:**
